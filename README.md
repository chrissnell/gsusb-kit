# GSUSBKit

A Swift driver for gs_usb (candleLight-class) CAN adapters on macOS, with no
kernel extension and no entitlement. Extracted from
[canopener](https://github.com/chrissnell/canopener), where it runs against a
live vehicle bus.

```swift
.package(url: "https://github.com/chrissnell/gsusb-kit.git", from: "0.1.0")
```

Requires macOS 15 and Swift 6.

## What it does

Enumerates `1d50:606f`-class adapters over `IOUSBHost`, claims the vendor
interface, runs the gs_usb handshake (`HOST_FORMAT` → `BT_CONST` →
`BITTIMING` → `MODE`), then reads, decodes, timestamps and transmits classical
CAN frames. It reconnects on its own, polls controller error state, and tracks
the adapter's crystal drift.

Classical CAN only. CAN FD and multi-channel adapters are refused at the
handshake rather than configured and hoped for.

## A default-constructed device cannot put a bit on the bus

`GsUsbOptions` defaults to `busAccess: .listenOnly`, which sets
`GS_CAN_FEATURE_LISTEN_ONLY`: the controller holds its TX pin recessive and
sends no acknowledgements, no error frames and no retransmissions. `send` on
such a connection throws `GsUsbTransmitError.listenOnly` rather than
reconfiguring the controller to honour it.

Transmitting takes `busAccess: .busActive`, spelled out at the call site. An
adapter that reports no listen-only support is refused rather than opened
bus-active, and the `MODE` flag word is re-derived on every reconnect so a
cable bounce cannot come back live.

## Using it

```swift
import GSUSBKit

struct Printer: GsUsbFrameConsumer {
    func consume(_ frame: GsUsbFrame) async {
        print(frame.timestampNs, String(frame.canID, radix: 16), frame.data)
    }
}

let device = GsUsbDevice(
    transport: IOUSBHostTransport(),
    consumer: Printer(),
    options: GsUsbOptions(bitrate: 500_000)
)

Task {
    for await state in device.states { print(state) }
}
Task {
    for await notice in device.notices { print(notice.label) }
}

await device.start()
```

`stop()` is mandatory: a started device's loop task holds it strongly, so
dropping the last reference to a running one leaks the device, the claimed USB
interface and the loop.

Frames go to a `GsUsbFrameConsumer` rather than an `AsyncStream` because the
ordering guarantee is load-bearing for transmit. `send` returns only once the
adapter has echoed the frame back, and the echo is published *before* the send
resolves — so a caller that sends and then reads its own recording cannot race
its own frame. A stream the host drained on its own schedule would lose
exactly that. Enqueue and return from `consume`; the read loop awaits it.

## Timestamps

`GsUsbFrame.timestampNs` is `CLOCK_REALTIME` nanoseconds since the epoch,
mapped from one of two sources, and `GsUsbDevice.timestampMode` says which:

- `.hardware` — the adapter's own 32-bit microsecond counter, stamped at frame
  receipt. `TimestampMapper` unwinds its ~71-minute wrap and re-anchors
  periodically against the host clock to track crystal drift.
- `.hostCompletion` — USB completion time, for adapters with no counter. Every
  frame in one bulk transfer lands within microseconds of its neighbours, so
  intra-burst ordering is smeared away.

`.hostCompletion` sets `timestampMode.isDegraded` and raises a notice at
connect. Anything that records frames should record which mode produced them;
the two are not interchangeable and a smeared capture has to stay identifiable
afterwards.

## Loss reporting

`seq` is generated by the driver and restarts at 0 for each connection, so a
hole in it is impossible by construction — and a host must not read its
absence as a clean capture. The adapter's own receive-FIFO overflow report is
the only upward signal that frames were lost, and it arrives twice:
`GsUsbStatistics.readStarvationEvents` and a `GsUsbNotice`.

## Testing without an adapter

Everything except `IOUSBHostTransport` is byte and integer arithmetic behind
the `UsbDeviceTransport` protocol, so the whole driver — handshake, decode,
timestamps, bus state, reconnect, transmit — is testable with nothing plugged
in. `GSUSBKitTestSupport` ships what that takes:

| Type | For |
|---|---|
| `ScriptedUsbTransport` | A `UsbDeviceTransport` that replays a scripted conversation, including surprise removal, stalled pipes, timeouts and write echoes. Successive `open()` calls replay successive sessions, so a reconnect test can script "removed mid-read, then healthy". |
| `CollectingFrameConsumer` | Buffers frames and republishes them as an `AsyncStream`. |
| `GsUsbVirtualClock` | Advances instantly and records what it was asked to wait for, so a test asserts on the *schedule* the driver produced. |

```swift
.testTarget(name: "MyTests", dependencies: ["MyKit", .product(
    name: "GSUSBKitTestSupport", package: "gsusb-kit"
)])
```

## gsusbprobe

```
swift run gsusbprobe
```

Reads a plugged-in adapter's identity, feature bits and bit-timing limits and
prints them. It never sets a mode, never writes to the bus, and never leaves
the adapter in a state that outlives it. `IOUSBHostTransport` is the one file
no test can execute, so `swift build --product gsusbprobe` is also what stands
between it and silent bit-rot.

## Modules

| Module | Responsibility |
|---|---|
| `GSUSBKit` | Wire codecs (`GsUsbProtocol`), bit-timing solver (`BitTiming`), device timestamp mapping (`TimestampMapper`), the USB seam (`UsbDeviceTransport`, `IOUSBHostTransport`) and the driver (`GsUsbDevice`). |
| `GSUSBKitTestSupport` | Test doubles, usable by downstream packages. |
